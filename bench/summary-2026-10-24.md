# P3 bench summary 2026-10-24

One run per model with `bench/run.ps1` defaults (20 tool trials, 20,000-token
prefill), llama-server build `b11868-78a8ae14b`, RTX 4070 Ti SUPER 16 GB (16,376
MiB). Decode = median of 3 after one discarded warm-up request; cold prefill = median
of 3 with `cache_prompt` false and no warm-up (cold by design). Every server was
started with `scripts/serve.ps1` defaults (`--fit` on, `-fa on`, q8_0 K and V, `-np
1`, `--temp 0.6 --top-p 0.95 --top-k 20`, `--reasoning-format auto`, `--no-mmproj`)
and `-Ctx 131072`; candidates load a local `.gguf` with `-m`, the baseline is the
logon-task server (`-hf unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ3_XXS`), benched while
running (it had already served requests); each candidate was a fresh start. Placement
figures come from separate starts with `-lv 4` and the same flags (candidates before
their bench start, Qwen3.6 after the matrix), each stopped before the next start.
Result JSONs (gitignored): `bench/results/20261024-170740-qwen3.6-35b-a3b.json`,
`20261024-171229-qwen3.8-27b.json`, `20261024-171344-gemma-4-26b-a4b.json`,
`20261024-171513-glm-4.7-flash.json`, `20261024-171548-gpt-oss-20b.json`. They
supersede the first matrix of the same day, whose decode median included the cold

Observations:

- All four candidates started at 131072 ctx on the first try; none needed the 65536
  retry, none exited, and no run had an HTTP error. Every model passed 20/20 tool
  calls (no wrong tool, no missing call, no empty argument).
- Only gpt-oss-20b fits all-GPU at 131072 ctx. `--fit` moved part of the MoE experts
  to CPU for Gemma (4 layers) and GLM (12 layers), and whole layers for the dense
  Qwen3.8-27B (16 of 66 layers, including 1,088 MiB of its 4,352 MiB KV cache).
- KV cache at 131072 ctx, q8_0: Qwen3.8 4,352 MiB (16 attention layers) plus 150 MiB
  recurrent state; GLM 3,596 MiB (K only, V 0 MiB); gpt-oss 1,632 + 10 MiB (SWA);
  Gemma 1,360 + 159 MiB (SWA); baseline Qwen3.6 1,360 MiB (10 attention layers)
  plus 63 MiB recurrent state.
- Discarded decode warm-up vs the median: Qwen3.6 136.9 vs 134.0 (server already
  warm), Qwen3.8 11.7 vs 11.7, Gemma 96.9 vs 96.9, GLM 83.8 vs 89.9, gpt-oss 168.0 vs
  170.4 tok/s. Measured decode runs spread at most 5.7 % (GLM 87.9 to 92.9).
- Cold prefill runs spread up to 28 % within one model (Qwen3.6 4,226 / 5,420 /
  5,351 ms); the others stayed within 8 %. The per-run figures in these two bullets
  come from console output that was not saved (UNVERIFIED beyond the medians in the
  JSONs); later runs tee the console to bench/results/<stamp>-<label>.log.
- Against the superseded matrix: decode Qwen3.6 +29.6 tok/s (104.4 -> 134.0, the
  warm-up fix); the candidates moved -1.1 to +3.5 tok/s. Prefill ms moved -0.1 to
  +10.1 %, tool p50 -17 to +8 %, VRAM peak +32 to +478 MiB.
- Qwen3.8-27B decodes at 11.7 tok/s and prefills 20K tokens in 19.0 s; the load log
  lists its `blk.64.nextn.*` (MTP) tensors as unused (relevant to P6).
- GLM-4.7-Flash (GGUF architecture `deepseek2`, MLA attention) decodes at 89.9
  tok/s and prefills 20K tokens at 1,454 tok/s. Separately, `--fit` left 12 of its
  layers overflowing (experts partly on CPU). This bench does not isolate what sets
  any model's prefill rate.
- Load warnings: Gemma, control-looking tokens `<eos>`, `<|tool_response>` and `</s>`
  not control-type (types overridden, `</s>` removed from EOG); GLM, `special_eot_id`
  and `special_eom_id` not in `special_eog_ids`; gpt-oss, `<|constrain|>`,
  `<|message|>`, `<|channel|>`, `<|start|>` set to USER_DEFINED and `<|end|>` removed
  from EOG. Gemma and gpt-oss templates do not support `preserve_reasoning`; Qwen3.8
  and GLM have it on by default. All four report `thinking = 1`.
- Sampling was the Qwen-tuned `serve.ps1` default for every model, not each vendor's
  recommended settings. Decode text was not inspected for quality (the decode bench
  uses `ignore_eos` on filler); every tool-call reply was well-formed.
- Not measured: prefill beyond 20K tokens, real agent tasks (the 20 tool prompts are
  synthetic, two tools, one turn), run-to-run variance across server starts (one
  bench run per model).
