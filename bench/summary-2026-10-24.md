# P3 bench summary 2026-10-24

One run per model with `bench/run.ps1` defaults (20 tool trials, 20,000-token
prefill), llama-server build `b11868-78a8ae14b`, RTX 4070 Ti SUPER 16 GB (16,376
MiB). Every server was started with `scripts/serve.ps1` defaults (`--fit` on, `-fa
on`, q8_0 K and V, `-np 1`, `--temp 0.6 --top-p 0.95 --top-k 20`, `--reasoning-format
auto`, `--no-mmproj`) and `-Ctx 131072`; candidates load a local `.gguf` with `-m`.
Placement figures come from a separate start with `-lv 4` and the same flags, stopped
before the bench start. Result JSONs (gitignored): `bench/results/20261024-163147-qwen3.6-35b-a3b.json`,
`20261024-165540-qwen3.8-27b.json`, `20261024-165707-gemma-4-26b-a4b.json`,
`20261024-165850-glm-4.7-flash.json`, `20261024-165934-gpt-oss-20b.json`.

Column notes: "CPU_Mapped MiB" is the sum of the `load_tensors: CPU_Mapped model
buffer size` lines. It includes tensors llama.cpp keeps on CPU even with every layer
on GPU (gpt-oss: 587 MiB with no `--fit` change, presumably the token embeddings,
UNVERIFIED), so it is an upper bound on what `--fit` moved. VRAM peak is whole-GPU
`nvidia-smi memory.used`; with no server loaded the GPU showed 1,317 to 1,519 MiB in
use (desktop and other apps). Idle with the model loaded: Qwen3.8 15,301, Gemma
15,429, GLM 15,472, gpt-oss 14,572 MiB (baseline 15,698).

Observations:

- All four candidates started at 131072 ctx on the first try; none needed the 65536
  retry, none exited, and no run had an HTTP error. Every model passed 20/20 tool
  calls (no wrong tool, no missing call, no empty argument).
- Only gpt-oss-20b fits all-GPU at 131072 ctx. `--fit` moved part of the MoE experts
  to CPU for Gemma (4 layers) and GLM (12 layers), and whole layers for the dense
  Qwen3.8-27B (16 of 66 layers, including 1,088 MiB of its 4,352 MiB KV cache).
- KV cache at 131072 ctx, q8_0: Qwen3.8 4,352 MiB (16 attention layers) plus 150 MiB
  recurrent state; GLM 3,596 MiB (K only, V 0 MiB); gpt-oss 1,632 + 10 MiB (SWA);
  Gemma 1,360 + 159 MiB (SWA); baseline Qwen3.6 1,360 + 63 MiB recurrent.
- Qwen3.8-27B decodes at 12.1 tok/s and prefills 20K tokens in 18.2 s; the load log
  lists its `blk.64.nextn.*` (MTP) tensors as unused (relevant to P6).
- GLM-4.7-Flash decodes at 91 tok/s but prefills at 1,453 tok/s, against 4,411 for
  Gemma, which has fewer overflowing layers (4 vs 12).
- Load warnings: Gemma, control-looking tokens `<eos>`, `<|tool_response>` and `</s>`
  not control-type (types overridden, `</s>` removed from EOG); GLM, `special_eot_id`
  and `special_eom_id` not in `special_eog_ids`; gpt-oss, `<|constrain|>`,
  `<|message|>`, `<|channel|>`, `<|start|>` set to USER_DEFINED and `<|end|>` removed
  from EOG. Gemma and gpt-oss templates do not support `preserve_reasoning`; Qwen3.8
  and GLM have it on by default. All four report `thinking = 1`.
- Sampling was the Qwen-tuned `serve.ps1` default for every model, not each vendor's
  recommended settings. Decode text was not inspected for quality (the decode bench
  uses `ignore_eos` on filler); every tool-call reply was well-formed.
- Not measured: prefill beyond 20K tokens, real agent tasks (the 20 tool prompts are
  synthetic, two tools, one turn), run-to-run variance (one run per model).
