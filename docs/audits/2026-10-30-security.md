# Security audit: local inference setup (local-inference-studio @ 0fd0cea)

- Date: 2026-10-30
- HEAD audited: `0fd0cea`
- Verdict: FAIL for enabling web fetch now (blockers B1-B7; B1-B3 critical/high)

Read-only audit: llama-server b11868, `claude-local.ps1`, `config/claude-settings.json`,
lis-guard, the user-scope `~/.claude/settings.json` every local session also loads, supply
chain, hygiene, logs. Nothing edited, no completion POSTed, no claude.exe run.

## Verdict: FAIL (for enabling web fetch now)

The deterministic controls (lis-guard, kill-guard) block destructive shapes well, but web
access adds an untrusted-input channel to a session that (a) can read every credential on
the box, (b) holds several exfiltration channels that need no approval, (c) is judged, for
anything no rule decides, by the same abliterated weights, and (d) can edit its own guard
scripts. Items B1-B7 below must close first; B1-B3 are the blockers.

## Before enabling web access (ranked)

B1 CRITICAL - Credentials are readable without approval and exfiltration channels need
none.
- Read side: user-scope allow `Read` (all files) and lis-guard's read-only grammar allow
  `cat` of any file (`docs/SETUP.md:584` "the hook allows `cat` of any file (ruling 15)").
  Not covered by any deny: `~/.claude/.credentials.json` (present, 2,459 bytes: Claude
  OAuth), `~/.cache/huggingface/token`, `~/.claude.json`, and `gh auth token` via user
  `Bash(gh:*)`.
- Send side, no classifier: user-scope `Bash(git:*)` (plain `git push` to the PUBLIC
  origin `https://github.com/kosm1x/local-inference-studio.git`), `Bash(gh:*)`
  (gist/repo/api writes; kept or stripped by auto mode is UNVERIFIED, `gh` is not in the
  stripped list), `Bash(docker:*)`. With web access: WebFetch URLs themselves, and
  user-scope `WebFetch(domain:github.com)` etc. become live the moment the project deny
  (`config/claude-settings.json:243-244` `"WebSearch", "WebFetch"`) is removed.
- `git-secret-guard.sh:44` TOKEN_RE has no `hf_` pattern and no Claude OAuth JSON shape.
- Fix: run local sessions without the user-scope rules (`claude --setting-sources
  project,local` plus `--settings`, UNVERIFIED on 2.1.314; re-add
  kill-guard/git-secret-guard in the per-run settings), or add per-run `deny` rules (deny
  beats a user allow): `Read(~/.claude/.credentials.json)`, `Read(~/.claude.json)`,
  `Read(~/.cache/huggingface/**)`, `Bash(gh *)`, `Bash(git push*)`, `Bash(git * push*)`,
  `Bash(docker run*)`, `Bash(docker exec*)`; mirror the paths in lis-guard as "critical
  read" denies. Strongest fix: run the web-enabled model as a separate Windows user or
  inside a WSL distro / container that holds no credentials and has an egress allow-list.

B2 CRITICAL - The fallback judge is the abliterated model itself.
- Every Bash call no rule or hook decides (any non-localhost curl, `python -c`, `node -e`,
  `python <model-written file>`, network tools) goes to the auto-mode classifier, which is
  the same uncensored weights (`docs/SETUP.md:322`). Nothing in the harness has a
  refusal-free model in mind: the classifier's value rests on the judge declining harmful
  actions. Mitigating: the classifier sees user prompt and tool inputs, not tool outputs
  (`docs/permissions-assessment-plan-2026-10-25.md:56-57`), so fetched page text does not
  reach it directly; but an injected main model writes the tool inputs it judges. A
  classifier timeout is a denial (SETUP.md:400,443), which helps.
- Fix: for web sessions do not use `auto`; use `-p` with `--permission-mode
  default`/`dontAsk` so an undecided call is a hard deny (V7: ask in `-p` = deny), or
  build ruling (16) with an aligned (non-abliterated) classifier model.

B3 HIGH - The session can edit its own guards and the server launch path.
- `claude-local.ps1:285,295,303` registers `python -I
  "<repo>/scripts/hooks/lis-guard.py"`, `loop-guard.py`, `verify-doc.py` from the repo;
  each hook re-reads its file per call. No ask/deny covers them: the ask list
  (`config/claude-settings.json:104-121`) protects `~/.claude`, `~/.ssh`, Windows, Program
  Files, `.env*`, `*.pem`, `*.key`, `token`, `.git` only, and `Edit(**)` is kept in auto
  mode. An injected session in this repo (or one whose edit outside cwd the abliterated
  classifier approves) can neuter lis-guard for the rest of the session, or edit
  `scripts/serve.ps1` / replace `bin\llama-server.exe`, which the logon task runs
  unattended (persistence; ACL lets any authenticated user write them too).
- Fix: copy the three hook scripts at launch to a per-run dir the session cannot write
  (ACL: read-only for the user, or hash-check before each call), add per-run deny
  `Edit(<repo>/scripts/**)`, `Edit(<repo>/config/**)`, `Edit(<repo>/bin/**)`, add those
  paths to lis-guard `CRITICAL_PATH` (lis-guard.py ~line 84), and run web sessions with a
  cwd outside this repo.

B4 HIGH - Interpreter payloads and model-written scripts are judged blind.
- `check_script` (lis-guard.py ~888-914) applies only `critical_verb` (shell verb regexes)
  to python/node script lines, so file deletion or network calls via language APIs are
  "not critical", the script is "not read-only", and the call goes to the classifier,
  which never sees script content (SETUP.md:338, 585). `python -c` / `node -e` payloads
  are not parsed (the docstring lists powershell/pwsh -Command, bash/sh -c, wsl, ssh
  payloads only). Write is allowed in cwd, so write-then-run is a standing route around
  the text scan.
- Fix: in web sessions deny `Bash(python *)`, `Bash(py *)`, `Bash(node *)` except the
  exact test rules already listed; or make lis-guard deny (not "no decision") any
  interpreter run of a file modified in the current session.

B5 HIGH - `-LisFull` removes the lean boundary.
- `claude-local.ps1:223-226`: `-LisFull` drops `--tools`, `--strict-mcp-config` and the
  empty MCP config. The lis-guard matcher is `Bash` only (`:288`), and kill-guard does not
  see the PowerShell tool (global CLAUDE.md), so a PowerShell tool call is unguarded;
  plugin MCP servers (playwright, claude-in-chrome) and the web app's connectors (Gmail
  send/forward, Drive share) may load (UNVERIFIED which ones load under a local base URL).
- Fix: refuse `-LisFull` with web (as `-LisTask` does, `:161`); guard or deny the
  PowerShell tool.

B6 HIGH - Browser-reachable API with a public, fixed key.
- CORS reflects any origin with credentials (live probe above) and the key `local` is
  hard-coded (`serve.ps1:114`) and published in this PUBLIC repo. Any web page open in a
  local browser, including one a browser tool drives for the model, can spend the single
  slot (`-np 1`: denial of service to the running session) or run prompts on the model.
  Chrome Private Network Access may block public-to-loopback requests (UNVERIFIED).
- Fix: random per-boot key in a user-only file read by both scripts (`--api-key-file`,
  UNVERIFIED on b11868); add `--no-webui`.

B7 MEDIUM - `--host` can be flipped and port 8080 is already open inbound.
- `serve.ps1:127-128` appends `-ExtraArgs` / `-ExtraArgLine` after `--host 127.0.0.1`;
  llama.cpp last-value-wins is UNVERIFIED, but a `--host 0.0.0.0` there would bind all
  interfaces, and the `VLMP` rule already admits TCP 8080 from any address on every
  profile, Program Any. Combined with B6's public key, that is LAN-wide model access.
- Fix: throw on `--host`/`--api-key`/`--port` in ExtraArgs; scope VLMP to its program;
  block inbound for `bin\llama-server.exe`.

## Other findings (not blockers for web access)

O1 MEDIUM - Supply chain: digest is fetched, not pinned. `install.ps1:41-73` takes the
expected SHA256 from the GitHub API at install time (trust-on-first-use against the same
origin as the zip) and `-SkipVerify` extracts unverified. Today's zips match. Fix: commit
the two expected digests for b11868 in `install.ps1`, and record/check the exe hash in
`serve.ps1`.

O2 MEDIUM - GGUF provenance. `docs/SETUP.md:75-91`: the default model is a third-party
abliterated build from the gated `orcarouter` repo, checked by byte length only
(`11637692000`), no `--revision` pin, `huggingface_hub` installed unpinned
(`SETUP.md:82`). Weights cannot be audited for trigger-conditioned behaviour, which is
another reason the model must not judge its own actions (B2). Positive: the embedded chat
template is replaced by the committed `config/chat-templates/qwen3.8-27b.jinja`
(`serve.ps1:95-98`). Fix: pin the HF revision and record a sha256 in `config/models.md`;
verify it in `serve.ps1` once per boot.

O3 MEDIUM - User-scope allow rules beyond B1 run without a judge: `Bash(rm:*)` (lis-guard
denies only `-r`/`-f`, `lis-guard.py:44`), `Bash(cp:*)`, `Bash(mv:*)`, `Bash(kill:*)`,
`Bash(pkill:*)`, `Bash(sed:*)`, `Bash(awk:*)`, `Bash(sqlite3:*)`, `Bash(timeout:*)` (a
command runner; whether auto mode strips it is UNVERIFIED). Fix: same as B1, do not
inherit user scope in local sessions.

O4 LOW - Scheduled task integrity: the action is fixed in Task Scheduler, but it executes
`scripts\serve.ps1` from a tree any authenticated user (and any session, B3) can modify.
Single-user box today. Fix: run the task against a copy under a user-only ACL directory or
add a hash check of `serve.ps1` + exe in a tiny launcher kept outside the repo.

O5 LOW - Env and accidental cloud use. `claude-local.ps1:177-196` sets BASE_URL,
AUTH_TOKEN `local`, all model aliases `local`,
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, attribution header off, and unsets
`ANTHROPIC_API_KEY` and the two subagent vars; values are restored in `finally`
(`:327-333`). User `settings.json` env holds no base URL or key. No OTEL vars are set.
Residual: OAuth credentials on disk (B1); calls to Anthropic for auth/connectors under a
local base URL are UNVERIFIED (check once with a proxy). Temp `lis-settings-<pid>.json` /
`lis-mcp-<pid>.json` (`:198-199`) hold no secrets and are deleted in `finally`.

## What the harness relies on refusals for

Directly: nothing in the deterministic layer (lis-guard, kill-guard, loop-guard, rule
sets) depends on the model refusing. Indirectly: the auto-mode classifier, the only judge
for undecided Bash calls, Write/Edit outside cwd and (once enabled) non-allowlisted
WebFetch domains, is an LLM whose refusals are the control, and it runs on the abliterated
model (B2). The `--append-system-prompt` policy (`claude-local.ps1:205-220`, "never work
around a denial") is advisory text, not a control. Compensating controls present:
lis-guard critical-write denies incl. nested payloads, kill-guard, ask rules (hard deny in
`-p`), project deny of WebSearch/WebFetch/Agent/Workflow, the lean 7-tool set, empty
strict MCP config, loopback bind. Missing: OS sandbox, network egress control, credential
isolation.

## Minimum set to reach PASS WITH WARNINGS for web fetch

1. Credential-free identity (separate user / WSL / container) with egress allow-list, or
   at least B1 denies and no user-scope inheritance. 2. No auto mode in web sessions, or
   an aligned classifier (B2). 3. Guards and launch files unwritable by the session (B3).
4. B4 interpreter deny; `-LisFull` refused with web (B5). 5. Random key, `--no-webui`,
   `--host` locked, 8080 rule scoped (B6, B7). 6. WebFetch only via
   `WebFetch(domain:...)`.
